ABOUT

저는 화면을 만드는 사람보다
구조를 설계하는 사람에 가깝습니다

보이는 결과만 완성하는 것이 아니라, 이후 수정과 확장까지 생각합니다. 그래서 어떤 태그가 적절한지, 반복되는 구조는 어떻게 나눌지, 클래스명은 얼마나 직관적이어야 하는지를 먼저 고민합니다.

HOW I THINK

저는 화면을 만들기 전에 먼저 구조를 정리합니다. 의미에 맞는 마크업을 고민하고, 사용자 흐름을 먼저 떠올린 뒤, 어떤 인터랙션이 필요한지 판단합니다. 그래서 작업이 끝난 뒤에도 설명 가능한 코드가 남도록 만드는 편입니다.

HOW I WORK

반응형과 접근성을 기본 전제로 작업합니다. 반복되는 UI와 코드는 모듈화해 정리하고, 처음 보는 사람도 이해하기 쉬운 클래스명과 구조를 지향합니다. 단순히 화면을 완성하는 것보다 유지보수 가능한 코드를 만드는 것을 중요하게 생각합니다.

STRENGTH

제가 보여주고 싶은 건
화려함보다 정리된 실력입니다

  • Modular Code

    반복되는 구조와 코드를 분리하며, 유지보수와 확장성을 고려해 작업합니다.

  • Clear Naming

    클래스명은 직관적이고 쉽게 이해되도록 고민합니다. 처음 보는 사람도 흐름을 빠르게 파악할 수 있는 구조를 지향합니다.

  • Responsive & Accessibility

    다양한 기기와 사용자 환경에서도 불편 없이 사용할 수 있는 화면을 중요하게 생각합니다.

  • Interactive Thinking

    작은 인터랙션도 단순 효과로 끝내지 않고, 사용자 흐름 안에서 자연스럽게 작동하도록 구현하려고 합니다.
