네 가지 작업 원칙과 실제 코드

아래 코드는 모두 제 프로젝트에서 발췌했습니다. 파일 이름을 누르면 GitHub의 해당 줄로 이동합니다.

의미에 맞는 태그를 먼저 고릅니다

화면을 그리기 전에 콘텐츠가 무엇인지부터 정합니다. 입력창에는 label을, 묶음에는 fieldset과 legend를, 이미지와 설명에는 figure를 씁니다. 입력 영역을 복제할 때도 id와 label의 연결이 끊기지 않게 번호를 다시 붙였습니다.

  • 9,108개 이미지 모두 alt 속성 작성
  • 2,804곳 label과 입력창을 for로 연결

반복되는 값은 토큰으로 묶습니다

색, 여백, 행간을 CSS 변수로 정의했습니다. 여백 토큰은 미디어쿼리 안에서 다시 정의해서, 같은 클래스가 기기마다 알맞은 여백을 갖습니다. 값 하나를 바꾸면 610페이지 전체에 반영됩니다.

  • 98개 디자인 토큰 정의
  • 590번 var()로 재사용

함수 하나로 여러 페이지를 움직입니다

페이지마다 스크립트를 따로 쓰지 않고, HTML에 data 속성만 적으면 동작하게 만들었습니다. 새 패널이 생겨도 스크립트는 고칠 필요가 없습니다.

  • 3,130곳 data-panel 사용 (610페이지)
  • 함수 1개로 전부 처리

어떤 기기에서도 같은 정보를 전합니다

기획서를 PC, 태블릿, 모바일로 따로 만들고 세 구간의 레이아웃을 각각 설계했습니다. 두 프로젝트와 이 사이트 모두 같은 기준을 씁니다.

어려웠던 점과 해결

가장 어려웠던 건 주소 입력 영역의 복사 기능이었습니다. 단순해 보였지만 원하는 시점에 값이 정확히 복사되지 않는 문제를 여러 번 겪었습니다. 자료를 찾고 테스트를 반복하며 이벤트 흐름을 이해한 뒤에야 안정적으로 구현했습니다.

디자인 단계에서 놓친 여백과 간격 문제는 CSS로 보완했습니다. 이 과정에서 시안을 그대로 옮기지 않고 구현 관점에서 디자인을 검토하는 습관이 생겼습니다.

어려웠던 점과 해결
